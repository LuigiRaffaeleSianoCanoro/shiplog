# Support

## Questions and ideas

Use [GitHub Discussions](https://github.com/LuigiRaffaeleSianoCanoro/shiplog/discussions) for:

- How something works
- Self-host setup help (see also [docs/self-host.md](docs/self-host.md))
- Feature ideas and design feedback before you open a large pull request

Search existing threads first. If your topic fits an open issue or discussion, continue there instead of starting a duplicate.

## Bugs and regressions

Use [GitHub Issues](https://github.com/LuigiRaffaeleSianoCanoro/shiplog/issues) with the bug report template when you have:

- A reproducible problem in Shiplog itself
- Broken behavior after an upgrade
- Documentation that is wrong in the repository (you can also send a small docs pull request)

Include versions, hosting context (managed vs self-hosted), and steps to reproduce when you can.

## Security

Do **not** open public issues for vulnerabilities. Read [SECURITY.md](SECURITY.md) and report through the private channel described there.

## Community

For broader conversation with other users and contributors, [mardelplata.dev.ar](https://mardelplata.dev.ar) is the community site we link to from project docs.

## What this project does not guarantee

Shiplog is open source software without a commercial support contract. Responses in Discussions and Issues are best-effort from maintainers and volunteers. For production incidents on your own infrastructure, you remain responsible for operation and recovery.
